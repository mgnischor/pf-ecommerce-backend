# Customers — Business Rules

Rules catalog for the **Customers** bounded context (`BR-CUS-*`), as required by `ai/BUSINESS.md §3`. Every rule is
enforced in the Domain layer (or, where it needs persistence or messaging, the Application layer), has stable error
codes, and is covered by unit tests tagged `[Trait("Rule", "BR-CUS-xxx")]`; the HTTP and messaging behavior is covered by
integration tests.

> **Ownership and sources.** The owner and requirement source below are placeholders to be assigned by the maintainers;
> the "Enforced in" column is the only traceability that exists today. Until a requirement or ADR is linked,
> "Source" reads `Initial domain model`.

## Model

`CustomerProfile` is the aggregate root: what the platform knows about a customer as a person. Its identifier is the
**account identifier** issued by Identity, so "the authenticated customer" needs no lookup and no other identifier is ever
exposed. It holds a name, the e-mail copied from the account, an optional phone, a preferred locale and a time zone.

```text
Identity: POST /auth/registrations ──▶ User + outbox: UserRegistered (no personal data)
                                                     └ CustomerRegistered (e-mail + what the customer typed)
                                                              │ identity.customer-registered
Customers: consumer ◀─────────────────────────────────────────┘
           └▶ customers.customer_profiles  ◀── GET / PATCH /customers/me
```

Customers owns the schema `customers` and never reads Identity's tables: everything it knows about the account reaches it
in the event. Staff accounts created by an administrator never raise `CustomerRegistered`, so they have no profile.

## BR-CUS-001 — Full Name Constraint

| Attribute      | Value                                                                                                                                                                                                                                                                                                                                                              |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Description    | The name is optional until the customer gives one (registration does not require it). Once given it can be changed but not removed. It is trimmed, every run of whitespace becomes one space, and it has 2 to 120 characters, no control character and at least one letter. No assumption is made about the structure of a name (any script, any number of parts). |
| Preconditions  | Registering with a name, or changing the name.                                                                                                                                                                                                                                                                                                                     |
| Postconditions | The normalized name is stored. Normalization to Unicode NFC applies wherever the runtime has ICU data (see "Known limitations").                                                                                                                                                                                                                                   |
| Error behavior | `Validation` failure on field `fullName`: `CUSTOMER_FULL_NAME_REQUIRED` (sent empty or `null`), `CUSTOMER_FULL_NAME_LENGTH` (params `min`, `max`), `CUSTOMER_FULL_NAME_INVALID`.                                                                                                                                                                                   |
| Implemented in | `FullName.Create`                                                                                                                                                                                                                                                                                                                                                  |

## BR-CUS-002 — Contact E-mail Invariant

| Attribute      | Value                                                                                                                                                                                                                                                                 |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Description    | The profile holds the e-mail of the account, trimmed and lowercase, at most 254 characters, ASCII, one `@`, a domain with a dot. It comes from the account and is read-only here: changing it belongs to Identity (BR-IDN-001), and no Customers endpoint accepts it. |
| Preconditions  | Creating the profile.                                                                                                                                                                                                                                                 |
| Postconditions | The e-mail never changes through this context. A profile cannot exist without one.                                                                                                                                                                                    |
| Error behavior | `Validation` failure on field `email`: `CUSTOMER_EMAIL_INVALID`. It is raised only while consuming the event, where it is a poison message: retrying cannot fix it, so it goes to the dead-letter queue.                                                              |
| Implemented in | `ContactEmail.Create`                                                                                                                                                                                                                                                 |

## BR-CUS-003 — Phone Constraint

| Attribute      | Value                                                                                                                                                                                                                                                                      |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Description    | The phone is optional and is an E.164 number: `+`, then 8 to 15 digits, the first not `0`. The API exchanges machine values and leaves presentation to the client, so spaces, hyphens and parentheses are rejected rather than stripped. Sending `null` removes the phone. |
| Preconditions  | Registering with a phone, or changing the phone.                                                                                                                                                                                                                           |
| Postconditions | The number is stored as sent (surrounding whitespace aside). The database has a check constraint with the same pattern as a safety net (ai/DATABASE.md §3.3).                                                                                                              |
| Error behavior | `Validation` failure on field `phone`: `CUSTOMER_PHONE_INVALID`.                                                                                                                                                                                                           |
| Implemented in | `PhoneNumber.Create`, `ck_customer_profiles_phone_e164`                                                                                                                                                                                                                    |

## BR-CUS-004 — Supported Locale Constraint

| Attribute      | Value                                                                                                                                                                                                                                                                           |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Description    | The preferred locale is one of the supported ones: `pt-BR` and `en` (the initial targets of `ai/API_CONTRACTS.md §7`, **to be confirmed by ADR**). It is matched case-insensitively and stored in canonical casing. A customer who gave none has `pt-BR`. It cannot be removed. |
| Preconditions  | Registering with a locale, or changing the locale.                                                                                                                                                                                                                              |
| Postconditions | The canonical tag is stored.                                                                                                                                                                                                                                                    |
| Error behavior | `Validation` failure on field `locale`: `CUSTOMER_LOCALE_UNSUPPORTED` (param `supported`), `CUSTOMER_LOCALE_REQUIRED` (sent empty or `null`).                                                                                                                                   |
| Implemented in | `CustomerLocale.Create`                                                                                                                                                                                                                                                         |

## BR-CUS-005 — Time Zone Constraint

| Attribute      | Value                                                                                                                                                                                                                                                                                                                                                          |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Description    | The time zone is an IANA identifier: `UTC`, or `Area/Location` (up to three segments, at most 64 characters) with an IANA area (`Africa`, `America`, `Antarctica`, `Arctic`, `Asia`, `Atlantic`, `Australia`, `Etc`, `Europe`, `Indian`, `Pacific`). A customer who gave none has `America/Sao_Paulo`. It cannot be removed. Every stored timestamp stays UTC. |
| Preconditions  | Registering with a time zone, or changing the time zone.                                                                                                                                                                                                                                                                                                       |
| Postconditions | The identifier is stored as sent. It is checked for **shape, not existence**: the runtime image is chiseled and ships no time zone database, and the domain must not depend on the host.                                                                                                                                                                       |
| Error behavior | `Validation` failure on field `timeZone`: `CUSTOMER_TIME_ZONE_INVALID`, `CUSTOMER_TIME_ZONE_REQUIRED` (sent empty or `null`).                                                                                                                                                                                                                                  |
| Implemented in | `CustomerTimeZone.Create`                                                                                                                                                                                                                                                                                                                                      |

## BR-CUS-006 — One Profile per Customer Account

| Attribute      | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Description    | A customer who registers themselves gets exactly one profile, created asynchronously from Identity's `CustomerRegistered` event, with the account's identifier as its own. The registration may carry a name, phone, locale and time zone, all optional. Only the e-mail is essential: an optional value that breaks its rule is **left out** (the profile gets the default and the customer can fix it with `PATCH /customers/me`) instead of costing the customer their profile. Delivery is at least once: the message is deduplicated through the inbox in the same transaction as the profile, and an account that already has a profile is left untouched. |
| Preconditions  | `identity.customer-registered` delivered to the consumer `customers.create-profile-on-customer-registered`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Postconditions | `customers.customer_profiles` has one row whose `id` is the account's. The first version is `1`. A redelivery changes nothing. The log names the fields that were left out, never their values.                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Error behavior | A message without a usable account identifier (`CUSTOMER_ACCOUNT_INVALID`) or e-mail (`CUSTOMER_EMAIL_INVALID`) is a poison message and goes to the dead-letter queue. Any other failure is retried.                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Implemented in | `CreateCustomerProfileOnRegistrationHandler`, `CustomerRegisteredConsumer`, primary key on `id`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |

## BR-CUS-007 — Own-Profile Access

| Attribute      | Value                                                                                                                                                                                                                                                                                                                                                                                |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Description    | `/customers/me` always means the authenticated account, taken from the validated token, never from the request: there is no route that names another customer, so object-level authorization (API1) holds by construction. Any signed-in account may call it; an account without a profile, such as every staff account, and a customer whose profile is not created yet, get `404`. |
| Preconditions  | An authenticated caller.                                                                                                                                                                                                                                                                                                                                                             |
| Postconditions | The response is about the caller and nobody else.                                                                                                                                                                                                                                                                                                                                    |
| Error behavior | `NotFound`: `CUSTOMER_PROFILE_NOT_FOUND`. A missing or invalid token is `401`, as everywhere (BR-IDN-003).                                                                                                                                                                                                                                                                           |
| Implemented in | `CustomersController` (`Authenticated` policy, no identifier in the route), `GetCustomerProfileHandler`, `UpdateCustomerProfileHandler`                                                                                                                                                                                                                                              |

## BR-CUS-008 — Partial Update with Version Precondition

| Attribute      | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Description    | `PATCH /customers/me` is a JSON Merge Patch (RFC 7396): a member left out keeps its value, a member sent replaces it, and only `phone: null` removes a value. `id`, `maskedEmail` and `version` cannot be changed (the body is ignored for them). The request must carry `If-Match` with the `ETag` of the version the client read; the precondition is checked before the data. The version advances once per **effective** change: an empty patch, or one that sends the values the profile already has, changes nothing and returns the current state. Nothing is applied unless every member is valid. |
| Preconditions  | The profile exists; `If-Match` present.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Postconditions | The response carries the profile and its new `ETag`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Error behavior | `400` for a missing `If-Match`; `PreconditionFailed` (`412`) `CUSTOMER_VERSION_MISMATCH` for a stale, malformed, weak-list or `*` value; `422` with the rules of BR-CUS-001 to BR-CUS-005; a lost write race is `409`.                                                                                                                                                                                                                                                                                                                                                                                     |
| Implemented in | `UpdateCustomerProfileHandler`, `CustomerProfile.Update`, `UpdateCustomerProfileRequest` (presence tracking), `AggregateRoot.Version` as the concurrency token                                                                                                                                                                                                                                                                                                                                                                                                                                             |

## BR-CUS-009 — Contact Data Masking

| Attribute      | Value                                                                                                                                                                                                                                                                                                                                                                                                                  |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Description    | The e-mail and the phone are never returned in clear (`ai/API_CONTRACTS.md §9.1`). The e-mail keeps the first character of the local part and the domain (`a***@example.com`); the phone keeps its `+` and last four digits and masks the rest (`+*********4321`). Masking happens when the read model is built, so no layer above can reveal the data by accident, and `ToString()` of both types is the masked form. |
| Preconditions  | Reading the profile.                                                                                                                                                                                                                                                                                                                                                                                                   |
| Postconditions | The response, the `ETag`, the logs and the telemetry contain no clear contact data.                                                                                                                                                                                                                                                                                                                                    |
| Error behavior | None: masking cannot fail.                                                                                                                                                                                                                                                                                                                                                                                             |
| Implemented in | `ContactEmail.Masked`, `PhoneNumber.Masked`, `CustomerProfileMapping.ToView`                                                                                                                                                                                                                                                                                                                                           |

## Data classification (ai/DATABASE.md §9)

| Column (`customers.customer_profiles`) | Class      | Notes                                                                                             |
| -------------------------------------- | ---------- | ------------------------------------------------------------------------------------------------- |
| `full_name`                            | PII        | Returned only to its owner; never logged or put in telemetry; anonymized by an erasure procedure. |
| `contact_email`                        | PII        | Returned only masked; never logged; copied from the account.                                      |
| `phone_number`                         | PII        | Returned only masked; never logged.                                                               |
| `locale`, `time_zone`                  | Preference | Not identifying on their own.                                                                     |

`identity.customer-registered` carries the e-mail and what the customer typed, so it is personal data in transit: it goes
through the outbox row of Identity and to the one Customers queue, and it is the reason the event is separate from
`identity.user-registered`, which stays free of personal data for every other consumer.

## Known limitations and open questions

- **NFC normalization needs ICU.** The production image is chiseled and runs in globalization-invariant mode, where
  `string.Normalize` returns its input unchanged. The rule (`ai/API_CONTRACTS.md §7`) holds in development, in CI and on
  any runtime with ICU data. Closing the gap means the `-extra` chiseled image (ICU and tzdata, which localization and time
  zone rendering will need anyway) and a documented change to `docs/container-exceptions.md` and the Dockerfile test.
- **Eventual consistency.** The profile appears a moment after registration; until then `GET /customers/me` is `404`.
- **No e-mail propagation.** Identity has no way to change an e-mail yet; when it does, it must publish an event for
  Customers to update `contact_email` (BR-CUS-002).
- **Erasure and retention.** The anonymization procedure and retention policy for the three PII columns (and the processed
  Identity outbox rows that carried them) are not implemented (`ai/DATABASE.md §9.1`).
- **Addresses** (`ai/ARCHITECTURE.md §2`: "profiles and addresses") are not modeled yet.
- **Supported locales** are an assumption pending the ADR named in `ai/API_CONTRACTS.md §7`.
